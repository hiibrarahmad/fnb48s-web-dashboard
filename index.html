Fast-charge trigger EXPERIMENTAL — actively requests a voltage change from the charger

Read this before using This sends a real command asking the connected charger to change its output voltage (up to 20V). It only works if the charger actually supports the selected protocol — plugged into a plain PC port or a non-fast-charge charger, it will simply fail, as it should. But if something voltage-sensitive is connected downstream and the charger does comply, it will see that higher voltage. Unplug anything you're not willing to risk before triggering. Unlike the read-side protocol, this was verified by capturing FNIRSI's own official app with Wireshark/USBPcap and matching its exact bytes — not guessed — but "verified bytes" isn't the same as "risk-free."

Verified protocols/IDs: QC2.0=0x00, QC3.0=0x01, Huawei FCP=0x02, Huawei SCP=0x03, Samsung AFC=0x04 (captured directly from FNIRSI's own app). Voltage encoding (little-endian millivolts) was confirmed at two data points (5.00V and 9.00V) and generalized to other voltages on that same confirmed field — same mechanism, not a new guess. There's no explicit "release" command observed yet, so a trigger stays in effect until the charger times it out or you unplug/replug.

About this tool

This is an independent, browser-based dashboard for the FNIRSI FNB48S USB power meter. It talks to the meter directly from Chrome/Edge using the WebHID API — no drivers, no install, and it runs alongside (or instead of) FNIRSI's own UsbMeter.exe desktop app. Everything happens locally in your browser; no data is sent anywhere.

Wiring: which port to use

The FNB48S has two separate USB connections and they are easy to mix up:

  • Pass-through ports (the big USB-A input/output) — for measuring: plug a charger into the input and a phone/cable into the output, and the meter reports what flows through it.
  • PC-link port — a separate, smaller USB-C port on the side of the meter, wired to its own controller. This is the one that must connect to your computer with a real data-capable USB-C cable for either this page or the desktop app to see the device.

How to connect

  1. Connect the FNB48S PC-link port to this computer with a data cable.
  2. Close UsbMeter.exe or any other app already talking to the meter (only one app can hold the connection at a time).
  3. Click Connect device above, choose the FNB48S entry (usually listed as “USB Input Device” or similar) in the browser's picker, and allow access.

What the readings mean

FieldMeaning
Voltage / Current / PowerMeasured at the meter, 100 samples/sec. Power is computed as V × A.
D+ / D−Voltage on the USB data lines — used by chargers to signal fast-charge modes (see the protocol table above).
TempInternal temperature sensor inside the meter (not the cable or charger).
Capacity (mAh)Current integrated over time since the session started/reset — how much charge has passed through.
Energy (mWh)Power integrated over time — how much energy has passed through.

Protocol details (for the curious)

The FNB48S speaks a small vendor HID protocol over 64-byte reports: three fixed handshake packets are sent to start streaming, then the meter pushes reports containing four 15-byte samples each (voltage and current as little-endian 32-bit fixed point ÷100000, D+/D− and temperature as little-endian 16-bit fixed point). This page implements that protocol client-side in JavaScript.

Troubleshooting

  • Picker shows nothing: wrong port/cable (see wiring above), or the device is already open in another app.
  • "Failed to open device": close UsbMeter.exe and any other program using the meter, then reconnect.
  • No numbers updating after connecting: open "Advanced / raw HID info" above to see raw bytes — if reports are arriving but values look wrong, the report framing on your OS/device may differ; that panel shows exactly what's being received to help diagnose it.
  • Browser unsupported: WebHID only works in Chromium-based desktop browsers (Chrome, Edge). It is not available in Firefox or Safari, or on mobile Chrome.

Extra features

  • Battery / capacity test — set a target mAh and expected charge current (mA) to get % charged, live and nominal time-to-full, C-rate, and a warning if the actual current strays far from what you expected.
  • Live protocol badge — a stabilized, averaged read of the D+/D− charging protocol match, separate from the instant reference table below it.
  • Alert thresholds — set a max V/A (or use a preset) and the matching tile flashes red if exceeded.
  • Event markers — drop a labeled marker (button or M) to line up something you did (e.g. "unplugged phone") with the graph.
  • Named recordings — separate from the live rolling buffer: start/stop a named capture, reviewable later, exportable as CSV.
  • Auto-reconnect — a brief USB blip retries the connection automatically for a few seconds before giving up.
  • Wake lock — keeps the screen from sleeping while connected, so a long charge test doesn't get interrupted.
  • Theme toggle and full JSON export are also available, top-right and in the Session card respectively.

Fast-charge trigger: how it was verified

Every other feature on this page reads data — it can't affect anything. The trigger feature is different: it writes a command that asks the connected charger to change its output voltage. Because of that, its command bytes were not taken from a community guess. They were captured directly from FNIRSI's own UsbMeter.exe using Wireshark + USBPcap while triggering each protocol from its own "Trigger" panel, then matched byte-for-byte, including reproducing its CRC-8 checksum exactly. The five protocol IDs and the millivolt-encoding scheme above are confirmed this way, not guessed. That said: it can only ask, and a charger that doesn't support the requested protocol will simply ignore it (which is what "Trigger failed" in the official app means, too) — but always know what's plugged in downstream before you send one.
